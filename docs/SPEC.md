## Продукт и игровой цикл

[A] Desktop-first браузерная 2D-стратегия сверху. Синие живые фрагменты краски борются с красной фракцией на постепенно обесцвечивающемся поле. Игрок управляет ограниченной армией как массой: рисует и растягивает форму, намеренно разделяет её на автономные группы, отдаёт независимые приказы и объединяет обратно. Присутствие перекрашивает территорию; бой противопоставляет охват концентрации. Источник: [§1](MASTER_SPEC.md#1-паспорт-продукта-цели-и-границы).

Цикл: старт → рисование → позиция/окраска → несколько направлений → split → независимые приказы → локальные столкновения → merge → цель → победа/поражение/повтор. Ориентир сессии 3–5 минут, без гарантии времени. Успех: минимум два осмысленных направления, влияние split/merge на исход, понятное без устных объяснений управление и повторяемая законченная партия. Нехватку интереса базового цикла не компенсировать новым контентом.

Капитан Блюм — обозначение синей стороны; Клякс — красной; Бесцветный — сюжетная причина потери цвета. Отдельный босс не обязателен, индивидуальные модели, способности и анимации героев не требуются в MVP [A/P]. Нейтральные персонажи на moodboard не добавляют третью фракцию или нового героя.

## Утверждённое [A]

- Одна законченная тактическая сессия на одной просторной вручную созданной карте. Базовая армия, красный противник, перестроение/растяжение/split/merge, окраска, бой/потери, UI состояния, обучение, Pause, Restart, итоговый экран.
- Гибрид A+B, умеренная детализация; B-static — компактные безликие сгустки, обычное движение только координатами. Без глаз, конечностей, мимики, хвостов, морфинга, перекатывания и постоянных частиц. Минимальный HUD без логотипа, арена для 2–3 направлений. [§2](MASTER_SPEC.md#2-художественная-спецификация--утверждённая), [DESIGN_GUIDE](DESIGN_GUIDE.md), D-01—D-03.
- TypeScript/PixiJS/Vite и статическая доставка Vercel, без backend. Генеративного ИИ внутри игры нет; детерминированный противник допустим. [§3](MASTER_SPEC.md#3-технологический-стек-и-архитектурные-ограничения), D-04/D-05, [ARCHITECTURE](ARCHITECTURE.md).
- Один этап за новый основной чат, ручная приёмка между этапами. На первом запуске только S−1. [§0](MASTER_SPEC.md#0-порядок-работы-codex--обязательно-прочитать-до-любого-кода).

## Предложения [P] и открытые решения [O]

Прототип управления: ЛКМ выбирает группу; drag по свободному полю строит линию, release подтверждает; короткий/пустой жест игнорируется. Cut: видимая кнопка + X и пересечение построения; Merge: выбрать первую, включить режим, указать вторую, сблизиться до конфигурируемой дистанции, однократно объединить и разрешить конфликт приказов. Горячие клавиши не заменяют кнопок. Автоматический разрыв натяжением **не утверждён** — D-06 Open, рассмотрение после S2.

Полилиния с фильтрацией, равномерными по длине слотами и стабильным назначением агентов; ограничение скорости и мягкое разведение — D-07 Proposed, проверка после S1. Без телепортов и сложного pathfinding на первой карте. Пространственная планировка центра, двух флангов, 1–2 сужений и 2–4 зон интереса, масштаб, камера и лимиты групп — гипотезы D-10, S0–S5.

PaintCell или заданные зоны; влияние присутствия, оспаривание красными, owner/насыщенность из модели; скорость, пороги и радиусы в LevelConfig. Начальная цель — доля контролируемых доступных клеток (D-08, S4). Поражение при потере всех синих; точный баланс — S4/S5. Бой: ближайший враг, радиус, HP, cooldown, фиксированный урон и удаление при HP≤0 без двойных атак (D-09, S5). Противник охраняет/патрулирует и реагирует детерминированно, без ML/GenAI.

Короткие событийные сигналы hit/death/split/merge и небольшой набор статичных финальных ассетов на S6 — [P], не разрешение постоянных эффектов. Все непроверенные числа, схемы API и настройки производительности остаются [P]. Журнал и последствия — [DECISIONS](DECISIONS.md).

## Исключённое [X] и границы

Мультиплеер, аккаунты, БД, экономика, крафт, строительство, длинная сюжетная кампания, коллекция героев, реальная CFD/жидкость, динамический морфинг каждого юнита, непрерывные частицы движения, генерация карт, серверная симуляция, любые runtime GenAI-функции. До изменения масштаба — без React, API и БД; Python не входит в runtime. Локальные скрипты для анализа/ассетов допустимы вне игры. WebSim необязателен, только демонстрация/UX, без переноса бизнес-логики и предположений о его API. Источники: §1, §3, [§9](MASTER_SPEC.md#9-работа-с-github-websim-и-vercel).
